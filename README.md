# Adrobot — обёртка над Keitaro

Две вещи поверх Admin API Keitaro:

1. **Создаватор кампаний.** Название, гео и оффер — на выходе кампания с доменом, группой,
   источником и двумя потоками: первый отправляет посетителей из указанных стран на Google,
   второй — всех остальных на выбранный оффер.
2. **Редактор офферов существующей кампании.** Добавление, удаление, возврат и закрепление
   долей. Правки копятся локально и уходят в Keitaro по кнопке.

Стек: FastAPI, SQLAlchemy 2, Alembic, httpx. Фронт — статические HTML/CSS/JS без сборки.

## Запуск

Нужен Python 3.10+.

```bash
git clone https://github.com/aminredfield/keitaro-adrobot.git
cd keitaro-adrobot

python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Настройки:

```bash
copy .env.example .env          # Linux/macOS: cp .env.example .env
```

В `.env` нужно заполнить:

| Переменная | Что это |
|---|---|
| `KEITARO_URL` | адрес Keitaro без `/admin` на конце |
| `KEITARO_API_KEY` | ключ из админки: Профиль → API ключи |
| `CAMPAIGN_PREFIX` | префикс имён кампаний, например `test_ivanov_` — добавляется сам |
| `KEITARO_DOMAIN` | домен новой кампании, как он называется в Keitaro |
| `KEITARO_GROUP` | группа кампаний, например `FORTESTS` |
| `KEITARO_SOURCE` | источник трафика, например `FORTESTS` |

Необязательные: `GEO_REDIRECT_URL` (куда уходит первый поток, по умолчанию Google),
`DATABASE_URL`, `ALLOWED_HOSTS`.

Домен, группа и источник задаются именами — их id приложение находит через API само.

Миграции и старт:

```bash
alembic upgrade head
uvicorn app.main:app
```

Интерфейс — на http://127.0.0.1:8000, документация API — на http://127.0.0.1:8000/docs.

## Миграции

База по умолчанию — файл SQLite `adrobot.db` рядом с проектом. Другую базу можно задать
через `DATABASE_URL` в `.env`: Alembic и приложение читают адрес из одного места.

```bash
alembic upgrade head                              # применить все миграции
alembic revision --autogenerate -m "что меняем"   # новая миграция после правки app/models.py
alembic downgrade -1                              # откатить последнюю
```

## Как пользоваться

### Новая кампания

Вкладка «Новая кампания»: название, коды стран через запятую (`MX, AU`), оффер из
автокомплита. Справа — схема того, что появится в Keitaro, она обновляется по мере ввода.

Перед созданием проверяется, что оффер, домен, группа и источник существуют. Если кампания
создалась, а поток — нет, кампания уходит в архив Keitaro, чтобы не оставалось пустышек.

### Редактор

Вкладка «Редактор»: кампания ищется по названию или id прямо в Keitaro.

| Действие | Что происходит |
|---|---|
| **Fetch streams from KT** | Забирает потоки из Keitaro. Потоки без офферов показываются одной строкой, без деталей. |
| **Добавить оффер** | Оффер появляется в потоке, доли пересчитываются. В Keitaro пока ничего не меняется. |
| **Remove** | Доля оффера становится 0%, строка сереет, остальные доли пересчитываются. |
| **Bring back** | Возвращает удалённый оффер в поток. |
| **Закрепить** | Доля оффера перестаёт меняться при пересчётах. Клик по самой цифре — задать долю вручную. |
| **Push to KT** | Отправляет поток в Keitaro и перечитывает его, сверяя цифры. |
| **Cancel** | Откатывает неопубликованные правки к состоянию Keitaro и снимает закрепы. |

Поток с неопубликованными правками жёлтый, с опубликованными — с зелёной полосой.

Правила, которые стоит знать:

- **Доли.** Закреплённые не трогаются, остаток до 100% делится поровну между остальными.
  Лишние проценты от деления получают первые офферы: трое делят 100% как 34/33/33, двое
  при закреплённых 25% — как 38/37.
- **Архив.** Удалённый оффер после публикации исчезает из Keitaro, но остаётся у нас серой
  строкой с кнопкой Bring back. Туда же попадают офферы, которые кто-то удалил прямо в
  Keitaro, — это видно после следующего Fetch.
- **Fetch — Keitaro главный.** Неопубликованные правки при Fetch затираются (интерфейс
  переспросит). Архив и закрепы сохраняются.
- **Push не пройдёт**, если сумма долей не 100% — так бывает, когда закреплены все
  оставшиеся офферы. Нужно снять закреп.
- **Push не затирает чужие правки.** Если поток поменяли прямо в Keitaro уже после Fetch,
  Push откажет и попросит сначала сделать Fetch.

## Устройство

```
app/
  main.py            сборка приложения, обработка ошибок, раздача фронта
  config.py          настройки из .env
  db.py, models.py   SQLAlchemy: кампании, потоки, офферы, привязки офферов к потокам
  keitaro.py         клиент Admin API — единственное место, где есть сеть
  shares.py          арифметика долей, чистая функция
  security.py        защита локального сервера от запросов с чужих сайтов
  schemas.py         схемы запросов и ответов
  services/
    creator.py       создание кампании с двумя потоками
    sync.py          Fetch: приводит базу к состоянию Keitaro
    editor.py        add / remove / restore / pin / push / cancel
  api/               тонкие роуты поверх сервисов
  static/            интерфейс
alembic/             миграции
tests/               тесты с поддельным Keitaro
```

Главная таблица — `stream_offers`. У привязки оффера две пары полей: `share`/`state` — что
видит пользователь, `synced_share`/`synced_state` — что лежит в Keitaro. Поток «не
опубликован», когда они расходятся. Push выравнивает вторую пару по первой, Cancel — первую
по второй, Fetch перезаписывает обе.

Несколько решений:

- У кампаний, потоков и офферов первичный ключ — это их id в Keitaro. Второго набора id и
  таблицы соответствий нет.
- После Push поток перечитывается из Keitaro и сравнивается с отправленным. Если цифры
  разошлись, пользователь получает ошибку, а поток остаётся неопубликованным.
- Обработчики синхронные: FastAPI выполняет их в пуле потоков, а код с обычными сессиями
  SQLAlchemy и обычным httpx читается проще. Нагрузка здесь — несколько человек.
- Справочники Keitaro (офферы, кампании, домены) кэшируются в памяти на минуту, чтобы
  автокомплит не тянул весь список офферов на каждую букву. Если оффера нет в кэше,
  список перечитывается — свежесозданный оффер находится сразу.
- Изменяющие запросы выполняются по одному (замок в памяти): каждый читает поток,
  пересчитывает доли и пишет обратно, и два одновременных посчитали бы доли по старым
  данным. Поэтому сервер нужно запускать одним процессом, без `--workers`.
- Тексты сетевых ошибок наружу не отдаются — только название ошибки. В них бывают
  внутренние адреса, а при кривом ключе в `.env` и сам ключ.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть: вместо Keitaro — класс `FakeKeitaro` в `tests/conftest.py`, который
повторяет нужные эндпоинты. Сценарии редактора в `tests/test_editor.py` идут в том же
порядке, что и в видео из ТЗ.

## Ограничения

- Авторизации нет: это внутренний инструмент, наружу его выставлять нельзя. Сервер
  отвечает только по именам из `ALLOWED_HOSTS` (по умолчанию `localhost` и `127.0.0.1`)
  и отклоняет изменяющие запросы, пришедшие со страниц других сайтов.
- Состояние оффера `disabled` в Keitaro не различается: оффер считается активным.
- Статистика кликов по потокам и офферам не показывается.
